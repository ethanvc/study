## 问题

有如下表：
```mysql
CREATE TABLE `users` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '自增主键',
  `name` VARCHAR(255) NOT NULL COMMENT '姓名',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci;
```

```mysql
# run below in first session.
START TRANSACTION;
INSERT INTO `users` (`name`) VALUES ('aa');

# run below in second session.
INSERT INTO `users` (`name`) VALUES ('aa');
```

问：两个的输出分别是什么？

答：第二个session的操作会超时。原因是，第一个session插入会持有name索引的排它锁，导致session2必须等待。

问：如果name不是唯一键，两个session的输出是什么？

答：session2 会先插入成功，然后session1根据是否提交才会执行完成。
如果session1执行commit，则用户先看到id=x，后看到id=x-1.
因此，依赖自增id进行同步的方案，要考虑如何处理这个场景。
