# 存储选型

| 特性     | MySQL                                    | ClickHouse                                     | Elasticsearch                          |
| -------- | ---------------------------------------- | ---------------------------------------------- | -------------------------------------- |
| 定位     | 关系型 OLTP，通用业务库                  | 列式 OLAP，分析/报表/日志                      | 分布式搜索与日志分析                   |
| 存储模型 | 行存                                     | 列存                                           | 倒排索引 + 列存（Doc values）          |
| 写入     | 高并发小事务写入，支持随机写、更新、删除 | 大批量追加写入优，不适合高并发小事务、频繁更新 | 高吞吐追加，支持更新，删除为标记后合并 |
| 查询     | 点查、简单聚合、事务查询                 | 大表聚合、多维分析、窗口函数、JOIN 大表        | 全文检索、聚合、复杂过滤、日志检索     |
| 事务     | 完整 ACID（InnoDB）                      | 无传统事务，最终一致性                         | 无多文档事务，近实时                   |
| SQL      | 完整 SQL，标准生态                       | SQL（方言），分析场景优化                      | REST/DSL 为主，SQL 为兼容层            |
| 扩展     | 主从、分库分表、云 RDS 垂直/水平         | 集群分片副本，水平扩展                         | 分片副本，水平扩展                     |
| 典型场景 | 订单、用户、配置、业务主库               | 数仓、BI、日志/指标分析、用户行为分析          | 搜索、日志、APM、监控指标              |

## 选型简要

- **MySQL**：强一致性支持、具备事务能力，适合业务需要频繁更新、删除、随机点查的场景。
- **ClickHouse**：适用于超大规模数据的聚合分析、报表统计、日志/指标分析等 OLAP 场景，写多读少、批量导入友好。
- **Elasticsearch**：针对全文检索、复杂过滤、日志检索与聚合分析场景表现突出，可作为实时检索入口，也常与 ClickHouse 联合使用（如 ES 实时检索 + CH 深度多维分析）。
- **K 线数据选型建议**：K 线数据的场景以写多读少、批量归档、聚合分析为主，推荐采用 ClickHouse 存储。如需高维条件检索或实时推送可考虑 Elasticsearch 做实时索引，结合 ClickHouse 实现高效回溯和分析。
