跨域问题的根源在于浏览器的同源策略（Same-Origin Policy）。它的核心逻辑是：**除非明确允许，否则一个域的脚本不能读取另一个域的资源。**

**什么是同源？**
只有当两个 URL 的以下三个部分完全相同时，它们才被视为同源：
- 协议 (Protocol, 如 http vs https)
- 域名 (Domain, 如 example.com vs api.example.com)
- 端口 (Port, 如 80 vs 8080)

跨越同源策略访问资源的标准方案为：CORS（跨域资源共享）。

它的工作机制分为两类：
- 简单请求 (Simple Request)：直接发送请求，浏览器在 Header 中带上 Origin。 如果服务器返回的 Access-Control-Allow-Origin 包含这个 Origin，请求就成功了。
- 预检请求 (Preflight Request)：对于像 PUT、DELETE 或带有自定义 Header 的复杂请求，浏览器会先发一个 OPTIONS 请求去探路。只有服务器点头（返回 200 OK 并带有允许头），浏览器才会发送真正的业务请求。

跨域涉及的关键请求头：
- Origin
- Access-Control-Request-Method 请求方法
- Access-Control-Request-Headers 请求将会携带的header列表

关键响应头有：
- Access-Control-Allow-Origin 取值*允许任何域访问
- Access-Control-Allow-Methods 允许的method
- Access-Control-Allow-Headers 允许携带哪些非简单的自定义请求头
- Access-Control-Allow-Credentials true。表示允许携带身份凭证如何Cookie、HTTP认证信息、TLS客户端证书
- Access-Control-Expose-Headers 允许使用的响应头
- Access-Control-Max-Age 预检请求可以被缓存多久（单位秒）
