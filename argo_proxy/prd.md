# 背景
在端到端测试当中，一个网站由多个团队维护，不同团队维护了各自的 http 代理服务器，用于统一接入请求、进行环境切换。不同团队使用不同域名或路径前缀对外提供 API。

# 目标用户与场景
- **用户**：测试、开发（本地/预发环境切换、多环境并行调试）。
- **场景**：按域名/路径将请求转发到对应团队代理，避免改 hosts 或全局代理。

# 需求

## 功能
- 根据**域名、路径**将请求路由到不同代理服务器。
- **代理列表**：支持 HTTP、HTTPS、SOCKS 代理；可增删改、启用/禁用。
- **匹配规则**：按域名或路径前缀匹配；规则可排序，先匹配先生效（或明确优先级策略）。
- **代理认证**（可选）：支持为代理配置用户名/密码，请求时自动带出。

## 交互与界面
- **Popup**：Chrome 右上角点击图标弹出。
- **Settings 页**：代理列表、域名/路径规则的新增与编辑（表单或简单列表即可）。

## Popup 弹出菜单设计

**尺寸**：宽度 320px，单列、自上而下布局，高度随内容。

菜单样式：
- 菜单如果有子菜单，使用箭头作为指示。
- 菜单如果是弹出页面，则不要加箭头。

---

**1. 启用 / 禁用**

- 表现形式：Switch + 文案（如「启用代理路由」）。
- 关：所有请求直连；开：按规则走代理。默认保持开启。

**2. Host 列表**

- 主菜单上一项，文案如「Host 列表」，可带数量或箭头表示可展开。
- 点击后打开子菜单；子菜单内展示「Host（或匹配条件）— 对应代理服务器名称」列表。
- 无规则时子菜单可展示「暂无规则」或为空，并引导去设置页添加。

**3. 设置**

- 主菜单上一项，文案「设置」。
- 点击后打开扩展的 Settings（Options）页。

---

**状态与反馈**

- 总开关关闭时：可灰显或标注「Host 列表」为已暂停，子菜单仍可打开查看配置。
- 子菜单可支持返回主菜单（如顶部返回箭头或再次点击「Host 列表」收起）。

## 非功能
- **安全**：代理凭证仅存本地，不上传。

# 验收标准
- 为某域名/路径配置代理 P 后，访问该域名/路径的请求经 P 转发，响应正确。
- 未匹配到规则的请求直连，不经过代理。
- 代理列表与规则在插件重启或浏览器重启后持久化保留。

# 边界（Out of Scope）
- 不做 PAC、不做系统级代理；仅限 Chrome 扩展能力内。
- 首版可不做：规则导入导出、多配置集切换（可列作 V2）。
